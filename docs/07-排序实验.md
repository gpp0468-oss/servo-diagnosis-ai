# 排序实验：从 0% 到 1.3%，以及一个恒等式

> 这是整个项目最值钱的产出：**一个核心功能的自我证伪。**

## 问题

分步诊断的核心问题：列了 9 条可能原因之后，**先查哪一条？**

理论上这是信息增益的经典应用，于是我做了「成本敏感信息增益排序」：

```
分数 = 这次检查能砍掉多少不确定性 ÷ 这个检查多贵

成本：实测 1.0 / 观察 1.5 / 替换 5.0
灵敏度：实测 0.90 / 观察 0.70 / 替换 0.95
```

## 第一次跑：降幅 0%

```
对比 48 个故障码
  原排序（实测>观察>替换）平均 3.52 步
  信息增益排序          平均 3.52 步
  降幅 0%
```

逐码持平，48 个码没有一个变快。

我以为是采样噪声，把每真值重复次数加到 300 —— 还是 0%。

## 一查：步数恒等于假设条数

再看一遍数字：平均 3.52 步、中位 3 步、最差 11 步。

然后去数数据：**多假设码 48 个，平均假设数 3.52，中位 3，最大 11。**

一个小数点都不差。

> **步数永远等于假设条数 —— 模拟从来没有收敛过一次。**
> 它不是在比较两种策略，它只是在数"每个码有几条原因"。

## 根因：似然模型方向搞反了

原公式：

```python
likelihood = 0.35 + 0.60 × 重合度(判据, 假设) × 灵敏度
```

逻辑上说得通：判据和假设越像，越可能确认这个假设。

但真实数据里**恰好相反**：

- 重合度最高的，是两条无关记录碰巧共享几个字
- 而"判据 i 对得上假设 i"这一对，重合度**最低**

因为判据写的是「更改某参数后，再次上电，查看该参数值是否保存」，假设写的是「参数写入出现异常」——两句话几乎没有共同词。

结果所有概率挤在 0.35–0.45，谁都推不动谁，后验永远到不了 0.9 的收敛线。

## 修正

```python
# 对角线：这条判据就是为这条假设写的
if i == j:
    return 灵敏度 × 判据特异性

# 非对角线：不是这条原因，但措辞重合时更容易被误读成"像"
return 0.10 + 0.55 × 语义重合度 × 灵敏度
```

收敛率从 **0% → 28%~71%**，步数不再等于假设条数。

## 更尴尬的发现：一个恒等式

修完后做对照：如果似然是单位阵（每条检查只能确认它自己的假设），"信息增益排序"和"只按成本排"会怎样？

答案：**数学上完全等价。**

推导：

- 单位阵下，信息增益是灵敏度的单调函数
- 而成本表恰好与灵敏度**反向**：实测最便宜（1.0）又最灵敏（0.90），替换最贵（5.0）
- 于是 `IG ÷ 成本` 的排序 ≡ `实测 > 观察 > 替换`

> **那个 0% 不是调参问题，是恒等式。**

## 修完之后：只值 1%

扫了 5 个收敛阈值 × 3 档灵敏度折扣 = 15 组参数：

```
阈值 | 旧策略 步/收敛 | 新策略 步/收敛 |  降幅
0.70 |  2.79   70% |  2.76   71% |   1.2%
0.75 |  3.04   63% |  3.00   64% |   1.3%
0.80 |  3.20   55% |  3.19   55% |   0.3%
0.85 |  3.32   43% |  3.32   43% |   0.0%
0.90 |  3.52   28% |  3.52   28% |   0.0%
```

**降幅 0.0% – 1.3%，没有一组超过 5%。**

原因很朴素：

- 各条检查的信息增益都挤在 **0.087 – 0.181**
- 最大比值只有 2.1
- 而成本差（1.0 对 1.5）直接把它吃掉了

> **信息量的差别，被成本差抹平了。**

## 为什么没删掉这个功能

因为 1% 的原因不在算法，在数据。

- 26 个码判据为空
- 其余判据大量是"查看 / 测量……"，特异性集中在 0.5–0.7

**判据区分不开，信息增益就永远算不出差别。** 判据质量一旦上来，它就是核心。

## 复现

```bash
python diag_rank.py            # 汇总：各阈值下的步数/收敛率/降幅
python diag_rank.py EB00.1     # 单码排序表
python diag_rank_show.py       # 体检报告 + 逐码新旧对比
```

不需要向量模型，纯计算。
